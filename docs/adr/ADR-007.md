# ADR-007: Identity is resolved by the core from platform_identities; production auth uses short-lived HTTPS link challenges with Argon2id, never chat passwords

Status: Accepted
Date: 2026-09-11

## Decision

The mediator stamps a Principal from platform_identities on every event; adapters have no field for an account id. Account creation links the current identity in one transaction; linking a new vendor issues an auth_challenges row (SHA-256 token hash, 10-minute TTL, single use) delivered as an HTTPS URL plus an 8-char code usable from an already-linked chat; the Tapir web app consumes it with CSRF protection, generic errors, per-IP/per-challenge rate limits and an auth_audit_log row, then injects AccountLinkCompleted through the normal inbound sink. Passwords are Argon2id via Bouncy Castle's pure-JVM Argon2BytesGenerator; recovery codes are hashed and single-use. The DM-password fallback is not built.

## Alternatives

Trusting actor.account_id from the wire as the current code does; DM password collection; OAuth via vendor identities only; JWT sessions in chat; argon2-jvm (JNA to native libargon2, worse for native-image).

## Consequences

No secret ever transits a chat vendor; identity flows are core code shared by all vendors; unlinked principals reach only identity flows and help; the web process is optional for MVP and required for cross-vendor linking and restore; delivery preferences attach to the account and its channels.
