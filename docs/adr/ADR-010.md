# ADR-010: Matrix DMs are end-to-end encrypted from the first Matrix slice using Trixnity 5.x with the vodozemac crypto driver behind a Kotlin shim, with a time-boxed spike and an out-of-process escape hatch

Status: Accepted
Date: 2026-09-11

## Decision

Use Trixnity 5.8.1 (de.connect2x.trixnity: trixnity-client, trixnity-crypto-driver-vodozemac, a JVM repository module) from a small Kotlin module compiled by Mill kotlinlib that implements the Scala ChatAdapter trait with runBlocking on the calling virtual thread. The Trixnity repository holds device keys, Megolm sessions and the sync batch token together (on the same Postgres in a `matrix` schema if the slice-7 spike verifies the Exposed repository, else SQLite on a named volume backed up in the same job as pg_dump), with a startup divergence check against the last inbound Matrix event. Direct-room invites are accepted from any MXID (allowlist, rate limit, leave after 10 minutes without a message) so first contact works; non-direct rooms only from a linked MXID. Sends use txnId = sendKey, reactions txnId = sendKey:r{i}; MSC3381 polls stay behind an off-by-default flag. Slice 7 opens with a two-day spike and a written go/no-go: if the Kotlin bridge or E2EE proves unworkable, the Matrix adapter runs out of process over a local socket speaking the same ChatAdapter contract.

## Alternatives

matrix-nio in Python (moot after ADR-001; also a 7-week-old vodozemac migration after a 21-month gap); Trixnity's libolm driver (deprecated crypto library); hand-rolling the client-server API without E2EE (a product compromise for a medication bot); matrix-rust-sdk FFI on the JVM (Android-oriented bindings, unverified for desktop JVM).

## Consequences

Element-default encrypted DMs work; Kotlin is confined to one adapter module; Trixnity's single-company maintenance (connect2x, monthly releases) and the coroutine bridge are the two named risks, both bounded by the checkpoint; the Matrix E2EE smoke test runs in CI against a Synapse testcontainer from slice 7; device verification UX for a bot must be documented.
