# ADR-022: Images are rendered from a typed scene tree through SVG profile 1 and a resvg child process

Status: Accepted
Date: 2026-11-13

## Context

Dosegram sends status images into a private chat: the mood blob, the daily summary, adherence calendars, the hydration vessel and the weekly report. Research brief 04 compared seven rendering stacks, and VISUALS_AND_ANALYTICS adopted its pipeline. The service runs on a 256 MB heap beside medication reminders, user-entered text reaches the images, and every image needs a text equivalent with the same numbers. The spike note [docs/spikes/render-pipeline.md](../spikes/render-pipeline.md) records the measurements this record relies on.

## Decision

1. The module `report-renderer` is pure. It turns an immutable view model into a scene tree of eight node types, and the scene into SVG text in "Dosegram SVG profile 1". It has no dependency and no file, network, process or AWT access; a test scans its imports.
2. Each card template returns the scene, the text equivalent, a neutral constant file name and the spoiler flag from one view model. A test asserts that every number drawn as a value appears in the text equivalent.
3. Colours, the type scale and the font pack are tokens in the module. Templates name roles and ask the copy port `ImageCopy` for every word; scene lints check minimum sizes, contrast, the palette whitelist and a non-colour channel on every status mark.
4. Rasterisation is a port, `Rasteriser`. The adapter `report-renderer.resvg` starts one resvg 0.49.0 child process per image, with SVG on standard input, PNG on standard output, pinned fonts only, a 5 second timeout, a 2 MB output limit and at most two concurrent processes. Every failure is a typed value and the caller sends the text equivalent.
5. Text is measured from a committed table of advance widths derived from the pinned font files, so layout and the SVG goldens need no native tool.
6. The font pack is IBM Plex Sans (400, 500, 600), IBM Plex Sans Condensed (500) and Geologica (600), all SIL OFL 1.1, vendored in `report-renderer/fonts` with checksums in `THIRD_PARTY_NOTICES.md`.

## Alternatives

| Alternative | Why it was not chosen |
|---|---|
| A Java2D painter over the same scene tree | No colour emoji, pixels tied to one JDK build, about 6 MB of heap per render. It stays the documented fallback and is not built, because resvg met every measured target |
| JSVG or Batik inside the JVM | Brief 04 measured unshaped right-to-left text in JSVG; Batik is heavy and has needed security fixes |
| Binding the resvg library in process | A native fault would stop reminder delivery; the process start costs about 40 ms, which is not the constraint |
| Measuring text with a `--query-all` pass of resvg | One more process per render, and goldens that only run where the binary exists. The table agrees with resvg within 2 percent |
| A chart library | Six chart shapes are needed; in-repository primitives give control of the visual language and add no dependency |

## Consequences

- The rasteriser, its version and the font pack are part of every pixel golden. Changing any of them regenerates `report-renderer/resvg/test/resources/goldens/pixel-hashes.txt` in the same change.
- The adapter lives in `report-renderer/resvg`, not in `infra` as ROADMAP G1.9 sketches, so that the render track adds one self-contained build block. Moving it is a package move.
- Characters outside Latin, Greek and Cyrillic are drawn as U+FFFD until an Arabic, a Hebrew and an emoji font join the pack.
- The daily summary places each domain icon at the middle of its halo segment, not at its start as VISUALS section 4.7 states, so the halo of 300 px radius and the domain rows fit the 1080 by 1350 canvas. It shows medication as one pooled line at every privacy level.
- The calendar legend names "Skipped" and "Not confirmed" apart, because the two "none taken" glyphs of VISUALS section 6.7 would otherwise share one legend entry.
- The container build stage for resvg, the asset store, the `file_id` cache and the report queue are separate slices (G1.9 image part, G1.10, G4.3).
