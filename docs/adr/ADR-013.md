# ADR-013: Interaction acknowledgement policy — ack before work, declared visibility, no defer for form-opening actions, Telegram's answer is single-shot

Status: Accepted
Date: 2026-09-11

## Decision

The mediator acknowledges before the inbound insert and outside the per-chat executor, driven by static declarations: component actions defer with an update; commands defer a reply with the visibility declared on CommandSpec; actions flagged opensForm are not deferred — the mediator verifies the MAC, resolves the principal with one indexed read and opens the modal within the budget, running database work on FormSubmitted; the adapter watchdog acks with the same declared type at 1.5 s (Discord) / 2 s (Telegram) measured from the interaction's creation timestamp and is disabled for opensForm tokens, with an explicit, counted fallback to FormRunner if the deadline is missed. Telegram's profile is transientAck = true, deferrable = false: cheap toasts are computed before any transaction and answered within about 1 s; a later toast degrades to a short auto-deleting message or is folded into the edited reminder. A handler that returns a visibility different from the declared one is delivered as a follow-up message.

## Alternatives

Revision 1's 'defer every interaction immediately' (makes Discord modals unreachable and fixes the wrong ephemeral flag for slash replies); acking inside the keyed executor after the inbound insert (a queued chat eats the 3 s budget); treating Telegram like a deferrable vendor (drops every post-ack toast).

## Consequences

Discord modals work for Add note, Correct time and wizard text steps; /account is ephemeral and /today is not, by declaration; 'This interaction failed' is avoided within the real budget rather than a receipt-relative one; the conformance suite covers modal-on-modal-profile, visibility mismatch, toast-after-auto-answer and deadline auto-ack; ack latency is measured from creation time.
