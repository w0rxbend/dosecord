# ADR-008: Migration is an in-repo greenfield rewrite delivered in thin slices with atomic deletion of the Python services and Kafka; no code or data migration

Status: Accepted
Date: 2026-09-11

## Decision

Rebuild inside the existing repository as a Mill build, salvaging only language-neutral assets — the UX specification, the envelope and payload shapes (transcribed), the 13-table schema as Flyway V1 with corrections, the transaction shapes, copy, menu trees and callback payload shape; ship slices 0-8 as individually green PRs; delete the discord.py bot, the backend service, all Kafka code and compose services in the same PR that lands the JDA Discord adapter; drop the dev Postgres volume since there is no production data; keep docs/MEDICATION_REMINDER_UX.md as the spec with the resolved lifecycle questions appended and replace the Kafka sections of the production plan with this document. Reuse is quantified honestly: 422 lines of contracts and 201 lines of models in a 2,307-line, 3-commit repository, none reused as executable code.

## Alternatives

Greenfield repository (loses history); parallel run of old and new bots (nothing to protect); big-bang rewrite in one PR; staying in Python to 'reuse' code that the design refactors anyway (a few hours of transcription, not a lens).

## Consequences

Each slice leaves a runnable system; the console adapter in slice 1 and the zero-core-files rule for the Telegram slice give early, mechanical proof of the architecture; the owner never maintains two stacks at once; packaging defects from the gap map (three unpinned Poetry projects, gitignored lock, PYTHONPATH hacks, broken DB URL scheme) disappear in slice 0; the Matrix spike at slice 7 is time-boxed with a written go/no-go.

## Addendum (2026-09-20)

This ADR originally deleted the Python services in the same PR as the Discord adapter "so there is never a half state". The Python path cannot start (R70) and double-executes every command (R86), so there is no working state to protect; the deletion moved to M0.2 (docs/ROADMAP.md, section 4, M0). The consequence of this ADR — the owner never maintains two stacks at once — is preserved.
