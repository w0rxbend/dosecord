# ADR-014: Dosegram pivot — Telegram is the only chat platform, the product is renamed, and Discord, Zulip and Matrix are retired in one step

Status: Accepted
Date: 2026-11-13

## Context

Dosecord was a Scala rewrite of a Discord medication-reminder bot, planned as a multi-vendor system (Discord first, then Telegram, Zulip and Matrix; ADR-005, ADR-010). The owner has dropped Discord and wants a Telegram-native health record keeper with a bot and a Mini App, with the emphasis on generated images, analytics and the Mini App. At the time of the decision the repository held 256 Scala files and 1,074 recorded tests, about 85 percent of the main code named no Discord symbol, and no measured defect was caused by the stack (docs/research/01-repo-inventory.md, commit `88772f0`). The owner-use week on Discord never completed, no user depends on the Discord bot, and no production data exists.

## Decision

Telegram is the only chat platform. The product, packages, artefacts and repository are renamed to Dosegram. The repository is migrated in place: the medication engine, the mediator, the outbox and the console adapter stay; `adapter-discord`, the JDA dependency and the Zulip and Matrix profiles, settings, markup branches and plans are deleted in one step, with no period of coexistence. ADR-010 is withdrawn. The language, build and database decisions (ADR-001, ADR-002, ADR-003) stand. The product gains a second surface, a Telegram Mini App, on the same backend.

The document set promoted to `docs/` on the same date governs: `ROADMAP.md` for delivery order and status, `PRODUCT_SPEC.md`, `ARCHITECTURE.md`, `BOT_UX.md`, `MINI_APP.md` and `VISUALS_AND_ANALYTICS.md` for their subjects (ROADMAP section 0.1). The Dosecord roadmap and design move to `docs/archive/` as the evidence index of the inherited slices and the detailed reference for the kept engine. The old slice identifiers (`M`, `UX`) name inherited evidence only; new slices use the prefix `G`.

Decisions that follow from the pivot are recorded in their own records, each written in the slice that first implements it, after the spike that could change it (ROADMAP section 1.7): ADR-015 to ADR-029.

## Alternatives

Keeping Discord as a second adapter until Telegram reaches parity (doubles the conformance work and keeps a JDA dependency, eight source files and a conformance profile alive for a platform the owner has dropped); a new repository named `dosegram` that copies the kept modules (loses the Git history that explains the engine's invariants and leaves two repositories to maintain during the transition); writing all sixteen follow-up records at once (seven of them depend on spike verdicts and would be accepted before their evidence exists).

## Consequences

One product name and no retired vendor in code or configuration, enforced by `scripts/check-vendor-symbols.sh`; guidance documents may not teach a retired command, setting or module, enforced by `scripts/doc-lint.sh`, while history may still be described. `ChatAdapter` and `ChatMediator` remain with two adapters, Telegram and console, so the simulation keeps its transport. The multi-vendor parts of earlier records lose their subject: ADR-001, ADR-005, ADR-006, ADR-007, ADR-010 and ADR-013 each carry an addendum of this date. The Flyway baseline was renamed in place, so a database created from the Dosecord baseline must be recreated; none holds real data. Discord credentials must be revoked by the owner (ROADMAP owner action OA-2), and the GitHub repository rename is an owner action (OA-3). Costs: the Discord evidence (suite A, the live spike of M0.8, the M2.1 and M2.2 slices) is voided and not replaced until the Telegram walking skeleton exists.
