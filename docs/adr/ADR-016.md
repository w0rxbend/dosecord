# ADR-016: Identity and Mini App authentication

Status: Accepted
Date: 2026-11-13
Supersedes: ADR-007

## Context

ADR-007 planned passwords with Argon2id, recovery codes and an HTTPS link challenge. ADR-014 made Telegram the only chat platform, and the Mini App became the second way into the same account. A Mini App receives signed launch data (`initData`) from the Telegram client; research brief 02, section 11.3, gives the two published ways to check it, and research brief 06, section 4, recommends the session design. ARCHITECTURE section 9.2 states the rules as API-02 to API-09. ROADMAP slice G1.12 builds the first part.

## Decision

1. The Telegram identity is the account. The core still resolves identity from `platform_identities`; no request carries an account id (carried over from ADR-007). The Mini App never creates an account: an unknown Telegram user is answered with 403 `account_required` (API-04).
2. The Mini App presents `initData` once, in the body of `POST /api/v1/session`. The server limits it to 4096 bytes, refuses a duplicate key, checks the signature, accepts an `auth_date` that is at most 300 seconds old and at most 60 seconds ahead, and requires a numeric user id that is not a bot.
3. A value with a `signature` is checked with Ed25519 over `<bot id>:WebAppData` and the sorted fields, against Telegram's production key. Another key is a setting that start-up refuses in production (API-02).
4. A value without a `signature` is refused with `client_too_old`, unless `MINIAPP_HMAC_FALLBACK=true`; then the `hash` is checked with HMAC-SHA-256 and compared in constant time (API-03). The verifier receives the derived key `HMAC_SHA256("WebAppData", bot token)`, never the token.
5. A valid value is exchanged for an opaque session token of 256 random bits. The token is returned once and held by the client in memory; the server keeps its SHA-256. No cookie is set. `initData` is not stored: only its SHA-256 is kept, to detect a repeat (API-05).
6. A session ends after 15 idle minutes or 12 hours. An account has at most five; the oldest is evicted. The same `initData` presented again inside its window issues a new session, ends the earlier one and writes audit event `initdata.reused` (API-06, API-07). One Telegram user may exchange six times per minute.
7. Every other route takes `Authorization: Bearer <token>`. An unknown token answers 401 `unauthenticated`, an expired session 401 `session_expired`.
8. No password, recovery code or link challenge is built. Sensitive operations will need a step-up confirmed in the chat (API-09, ROADMAP G3.8).

Rejected alternatives: HMAC validation as the primary path (the verifying process would hold a key that can mint launch data for any user), `initData` on every request (not revocable, replayable for its whole window), a cookie (third-party iframe behaviour differs per client and brings back request forgery), a self-contained token (no revocation).

## Addendum, 2026-11-13: durable sessions

The row "Table `miniapp_sessions` with a deletion job" of the table above is closed. Sessions are rows of `miniapp_sessions` (ARCHITECTURE section 10.17): `PgMiniAppSessions` in `infra`, adapted to the port `SessionStore` by `PgSessionStore` in `app`, so a restart ends no session. The port method `deleteWhere` became `deleteEnded(idleBefore, createdBefore)`, which a store can answer with one statement. `last_used_at` is written at most once per minute (API-06). The table holds the two hashes as hexadecimal text and has no expiry or revocation columns yet. `InMemorySessionStore` remains for the suites of the `api` module.

## Consequences

- Whether `signature` belongs to the HMAC data-check string is unverified (research brief 02); the verifier includes every received field except `hash`. Spike G1.3 checks it on real launch data before the fallback is used with a real bot.
- `MINIAPP_ENABLED=true` is refused in production until checkpoint CP3-a, so none of the open rows above can reach a user.
- A stolen bot token allows minting launch data only where the HMAC fallback is on; with Ed25519 alone it does not.
