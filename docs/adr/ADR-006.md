# ADR-006: Interaction callbacks are 34-byte HMAC-signed tokens (46 chars base64url, 'dc:' prefixed on the wire) carrying a full UUID subject and a typed action registry

Status: Accepted
Date: 2026-09-11

## Decision

Every control carries version|key_id, mode (direct|slot), a UInt16 action from a registry whose entries declare opensForm, visibility and requiresSession, a 16-byte UUID subject, a 6-byte value and an 8-byte HMAC-SHA256 tag, base64url-encoded to 46 chars and sent as 'dc:' + 46 = 49 chars in both Discord custom_id and Telegram callback_data. Direct mode names a durable entity (dose occurrence) and is stateless and non-expiring; slot mode points at callback_slots for larger wizard/menu payloads. Keys rotate with two active key ids. Discord routes by prefix on component and modal custom ids (JDA needs no registered views or modals); Zulip/Matrix never receive tokens and resolve through rendered_messages.choice_map.

## Alternatives

Plain 'action:target:value' strings (forgeable); a server-side token table for every button; int64 short-id subjects; single-use tokens; a bare 46-char token matched by a literal leading '1' (revision 1's regex could never match a v1/k0 token — the review finding).

## Consequences

Fits Telegram's 64-byte callback_data and Discord's 100-char custom_id by construction (property-tested); buttons on week-old messages and across restarts keep working; forged or tampered payloads are rejected in the mediator with a toast and an audit row; the registry's opensForm and visibility flags drive the acknowledgement policy of ADR-013; the 6-byte inline value bounds direct tokens, so anything larger uses slot mode.
