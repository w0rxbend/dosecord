# ADR-009: Delivery is at-least-once through a vendor-owned outbox dispatcher with typed ops, vendor calls outside transactions, vendor-side idempotency where it exists and a bounded, flagged duplicate everywhere else

Status: Accepted
Date: 2026-09-11

## Decision

Outbox rows carry op (send|edit|finalize|delete|react), target, vendor, epoch and an ops_done bitmap. Each process claims only rows for vendors it hosts (advisory lock per vendor), so Matrix E2EE and Discord sends never leave the process holding the client. The dispatcher claims in a short transaction with a 60 s lease and attempted_at set, calls the adapter with no lock held, records the primary handle and choice_map immediately after the primary send and before any reaction, resumes reaction sub-ops from ops_done with per-op txn keys, and marks sent last. Discord uses setNonce (enforce_nonce is written by JDA); Matrix uses txnId = sendKey. Because Discord's nonce window is a few minutes and Telegram/Zulip have no key, the uniform rule is: a lease-expired send retried more than 2 minutes after attempted_at is sent once and flagged possible_duplicate. Retries use exponential backoff with jitter, 8 attempts then dead; only channelFatal errors mark a channel dead and trigger fallback; 'message is not modified' and duplicate-reaction errors are success by adapter contract; a synchronously delivered reply is recorded as sent with its handle, and its outbox row is an edit op that the dispatcher claims only if that record is lost.

## Alternatives

Holding the row lock across the vendor call; a pre-send lookup in a sent-messages table; at-most-once; a send-only outbox (revision 1's, which would re-send a synchronously delivered reply as a new message after a crash); a raw Discord REST route for enforce_nonce (unnecessary — both discord.py and JDA send it); claiming 'duplicates are impossible on Discord'.

## Consequences

Duplicates are bounded to one per crash on every vendor and are cosmetic: both copies carry the same occurrence token or choice_map row and the post-resolution finalize op edits every recorded handle; reaction-tier reminders never appear with dead controls; the dispatcher needs zero vendor knowledge thanks to the ChatError hierarchy; the gateway/worker split isolates the loop from adapters but cannot move a vendor's dispatch off the process that hosts it.
