# ADR-003: Kafka is removed; Postgres is the messaging backbone (transactional outbox, inbound dedupe, domain_events, LISTEN/NOTIFY)

Status: Accepted
Date: 2026-09-11

## Decision

Delete Kafka, ZooKeeper, Kafka UI and the outbox-publisher process. Adapters call the core in-process through the mediator; asynchronous edges are Postgres tables: outbox_messages (at-least-once with lease, backoff, dead-letter, op/target columns, vendor ownership), inbound_events (idempotency with replayed reply), domain_events (append-only CloudEvents-shaped log consumed in-process after commit), and LISTEN/NOTIFY as a wake-up. The CloudEvents envelope is kept as the row payload shape so a relay to NATS JetStream or Kafka can be added later behind an EventBus port.

## Alternatives

Keep Kafka (three extra processes and a broker for tens of rows a day; the request/reply gap, partition-key flip at account link and unauthenticated broker are structural); NATS JetStream now (a second stateful system with no consumer); Redis streams (no transactional enqueue).

## Consequences

Interactions are acknowledged within Discord's 3 s and Telegram's single-shot window because a button tap is a direct in-process call; every user intent is either fully applied with its reply and outbox rows in one transaction or visibly fails; per-chat ordering comes from a keyed executor of Ox channels plus row locks; the growth path is a relay reading domain_events/outbox, not a redesign.
